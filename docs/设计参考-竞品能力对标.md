# 竞品能力对标与落点说明

设计过程中参考了市面上的同类平台，用于校准能力口径与信息组织。
本文件记录**对标了什么、怎么落地到现有页面**，以及**哪些刻意没有照搬**——避免把「参考」做成「照搬」。

对标只改能力口径与信息组织，**不新增页面**（沿用「现有页面内增强」的方案）。所有能力都落在平台原有的字段、指标与环节上。

---

## 一、对标对象与可取之处

| 竞品 / 机构 | 官方可查的能力表述 | 本平台取用的点 |
| --- | --- | --- |
| **Encord**（Physical AI 数据平台） | 把物理 AI 数据拆成 **采集 → 扩展 → 标注 → 治理 → 部署反馈** 五个阶段，主张五段跑在同一个平台上，让「现场学到的教训」能回流影响下一次采集；提供 **embedding 检索 + model-in-the-loop 治理**找长尾；**AI 先标注、人复核不确定样本**（hybrid HITL）；**active learning 优先把不确定样本推给人** | 数据飞轮六环节、主动学习难例队列、预标注「候选而非结论」、人机一致率 |
| **Scale AI** | Physical AI 数据引擎；AI 辅助预标注降低重复劳动；**active learning 用来浮现稀有与困难场景** | 难例优先排序、机审命中率 / 改判率 |
| **北京人形 · 慧思开物 / RoboMIND 数据基地** | 全栈自研闭环：**采集 → 清洗 → 质检 → 标注 → 模型训练 → 真机评测 → 部署 → 数据回流**；**矩阵式采集**（真机 + 无本体同时采，跨机型跨场景复用）；场景可动态配置与组合重构 | 「全范式采集」（真机 · 无本体 · 仿真）、闭环链路命名与责任人 |
| **Topstar（与无问智科共建）** | Scan2Sim / Gen2Sim 批量生成多条件场景与**长尾边缘案例**；仿真数据自带完美 ground truth，真实数据用**自动预标注 + 人工复核**；**真机失败案例自动回流到仿真扩展**，形成「发现问题 → 补数据 → 升级模型」回路 | 长尾缺口转补采、难例回流（训练失败回传） |
| **无界动力 AnyPhys** | **负样本自动体系**，无需人工标注即可区分正 / 负 / 次优样本 | 失败样本专项、结果分层里的「失败 / 次优」口径 |
| **Labellerr / iMerit** 等 HITL 服务 | HITL 的本质是「模型标它会的，人标它不会的」；AI 预标注 + 人工复核 | 采纳建议 / 改判都回写一致率 |

> 上述表述均来自各平台公开页面与行业报道（详见文末来源）。**没有引用任何未公开的内部数字**。

## 三、刻意没有做的

1. **没有新增页面**。「数据飞轮」同类产品往往单开一个大屏，但本平台的信息架构已经承载了各环节，单开一页只会把闭环拆散。改为在看板顶部用一条可视链路串起来。
2. **没有把「智能」做成独立产品线**。预标注、机审、主动学习都挂回原有环节，不新增「AI 中心」这类导航项。
3. **没有让模型替代判定**。所有模型输出都以「候选 / 建议」呈现，采纳与改判都留痕并回写一致率——判定权始终在人。
4. **没有照搬套路化视觉**。没有渐变、毛玻璃、发光、装饰性星芒图标；能力类指标用与业务指标一致的工程化排版（等宽数字 + 细描边），靠信息结构区分而不是靠视觉特效区分。
5. **没有堆砌竞品术语**。能力表述全部改写成中文业务口径（如 active learning → 难例回流 / 主动学习），保留可读性。

## 四、补充对标：AIRS Airspeed（开源）

来源：https://github.com/airs-cuhk/airspeed — 开源具身智能数据生产平台（AIRS，2025）。

它的四项核心能力此前是本平台的缺口，已逐项补齐：

| AIRSPEED 能力 | 原文口径 | 本平台落点 |
| --- | --- | --- |
| **硬件-软件解耦** | "Any device that publishes standard ROS2 messages is compatible; the pipeline is configured entirely through YAML files without source code edits" | 新增「配置 → 接入契约」页：契约是受控资产，新增设备 = 写适配器 + 在会话配置里声明话题，核心采集服务零改动 |
| **ROS2 主题契约** | 每接口定义话题约定：`PoseStamped` / `Joy` / `JointState` / `Image` / `CameraInfo` / `Imu` / `PointCloud2` | 接入契约页 3 个接口契约 + 7 条流声明（话题 / 消息类型 / 时间域 / QoS / 字段抽取 / 速率 / 合规） |
| **创建时刻时间戳** | "header.stamp is the data-creation time … not the time the message happened to be published；header-less types are rejected" | 契约页明确"只接受带 header 的消息"，`/ft/left_wrench`（无 header）标红「不合规」，契约拦截记录给出处置 |
| **入库时边界校验** | "Boundary validation rejects malformed data (NaN/Inf) at ingest time" | 上传与校验中心新增「契约级校验」面板：header+时间域 / 必填字段 / 边界值 NaN·Inf / 跨流对齐 ≤1 帧 |
| **落盘后多格式转换** | HDF5 → Parquet / Zarr / LeRobot v3 / JSON Lines，各转换器运行前对源做内联校验 | 导出与交付页新增「格式与转换」页签，含转换工具名与"推送到 HuggingFace Hub" |
| **两层 YAML 配置** | Layer 1 会话 YAML（录什么）/ Layer 2 全局 YAML（用哪个适配器） | 契约页内置会话 / 全局 YAML 可切换查看器 |
| **时钟同步前提** | 局域网 chrony（毫秒级）/ 需要更紧用 PTP（微秒级）；远端无受控时钟则在采集侧打戳 | 契约页「时间域与时钟同步」面板（4 节点，远端头显未同步），并与采集端"时间未同步则阻塞录制"呼应 |

**刻意保持的差异**：AIRSPEED 是**采集侧的开源采集服务**（ROS2 + Python + HDF5）；本原型是**平台侧的产品形态**（三端 + 全生命周期闭环）。因此只吸收其"契约 / 解耦 / 前置校验 / 多格式"的**能力口径**，不照搬其命令行与工程实现——本平台面向的是项目经理、质检员与客户，不是 ROS2 开发者。
